# HF99 Windows and DOS synchronization (2026-10-17)

The Windows HF99 changes were user-verified before the DOS port. Synced sources:
- `snapshot/HF97/src/main.cpp`: stage dungeon spell results until their sound finishes; suppress premature input cursor; use the blue spell projectile
- `snapshot/HF97/src/DungeonSystem.cpp`: keep monster death and all loot denominations on the same logical row, retaining the death-row index when a quest message is appended
- `snapshot/HF97/src/OverworldSimulation.cpp`: field Kill prints only the death/reward result, not the fake 9999 damage row
- `snapshot/HF97/src/OriginalData.cpp` and `OriginalData.h`: construct a blue physical-tile-50 projectile variant (weapons retain red)
- `snapshot/DOS_RESUME_20261017_DIAG/source/main.cpp`: port of Windows spell sequencing and field presentation to the DJGPP DOS runtime
- `snapshot/DOS_RESUME_20261017_DIAG/source/OriginalData.cpp`: DOS-compatible graphic texture implementation
- `snapshot/DOS_RESUME_20261017_DIAG/build.sh`: compile updated main, DungeonSystem, OriginalData and OverworldSimulation rather than stale HF93 objects
- `snapshot/DOS_support/HF93_OriginalData_HF99.h`: **required compatible header** to replace local `src/HF93/src/OriginalData.h` before building. Its additional texture member is at the *end* to preserve offsets used by existing HF93 object files.

The DOS build additionally relies on original assets, DJGPP and preexisting object files on the authorized Windows machine; this GitHub snapshot is not yet a fully self-contained reproducing build. User savegames are not committed.

The Windows user's acceptance applies to Windows HF99. A successful DOS compile/link alone does not verify runtime spell effects. Validate the DOS game separately before release.
